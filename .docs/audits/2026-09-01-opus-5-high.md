## [1] MAJOR · CONFIRMED · scripts/validate.py:140

**What:** `check_skill_count()` calls `json.loads(CODEX_MANIFEST.read_text(...))` with no
`is_file()` guard and no `try/except`. Both guards exist in `check_versions()` one function above
(lines 111 and 116-117), so the omission is an inconsistency rather than a deliberate choice.

**Why:** it destroys the error report in exactly the situation the report exists for. `main()`
collects errors and prints them together at line 177-181; an uncaught exception at line 140 means
that block never runs, so **every** error collected so far is lost — including the accurate
`invalid JSON` message `check_manifests()` had already recorded.

**Failure scenario:** drop a comma in `.codex-plugin/plugin.json` and run
`python3 scripts/validate.py`. Verified: `check_manifests()` correctly records
`".codex-plugin/plugin.json: invalid JSON — Expecting ',' delimiter: line 3 column 3"`, then
line 140 raises `json.decoder.JSONDecodeError` and the script dies with a 9-line traceback. The
user sees a stack trace pointing at `validate.py` — as if the validator were broken — instead of
the one-line message naming their actual typo. Exit code stays 1, so CI still fails; what's lost
is the diagnosis, plus any other errors in the batch.

**Fix:** mirror `check_versions()` — return early if the manifest is missing, and wrap the parse in
`try/except json.JSONDecodeError: return`, since `check_manifests()` has already reported it.

**Outcome: fixed** (`scripts/validate.py:140-146`). Re-ran the reproduction: the validator now prints
`.codex-plugin/plugin.json: invalid JSON — Expecting ',' delimiter: line 3 column 3` and exits 1, with
no traceback.

## [2] MINOR · CONFIRMED · scripts/validate.py:129

**What:** the banner check is `f"║         {version}" not in readme` — a hardcoded 9-space indent
that constrains only the text *before* the version. Nothing checks the closing `║`, so the row's
total width is unvalidated.

**Why:** the check's purpose is keeping the README banner correct across a version bump, and it
passes the one case it's meant to catch. The banner is the first thing on the repo's front page.

**Failure scenario:** bumping 1.9.0 → 1.10.0, the natural edit is to keep the row visually centred
by leaving 9 spaces on both sides of the longer string. That yields a 24-character interior where
every other row in the box is 23. Verified: `validate.py` prints
`✓ 33 skills, manifests valid, versions aligned` and exits 0, while the rendered box has its right
edge jutting one column past the `╗`. The opposite error — rebalancing to 8 leading spaces, which
keeps the box square — is the one the validator *rejects*.

**Fix:** check the whole row rather than its prefix — match `^║(\s*<version>\s*)║` and compare that
interior's length against the nearest `╔═…╗` border above it.

**Outcome: fixed** (`scripts/validate.py:129-141`). Note both rows carry terminal text *after* the
closing `║`, so the patterns must not anchor to `$` — the first attempt did and matched nothing.
Re-ran the reproduction: the 24-wide row now fails with
`the 1.10.0 row is 24 chars wide but its box is 23`.
